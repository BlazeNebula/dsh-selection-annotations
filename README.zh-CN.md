# 划词批注

[English](README.md) · **简体中文**

在对话里选中一段文字，写下你的意见，它跟着下一条消息一起交给 AI；AI 的答复会按条回到你指过的那个位置。

「把上面第三段那句话改一下」这种话不用再写了。你把它划出来就行。

---

## 先装上

在 DSH 的「设置 → 插件」里装。能访问 npm 的直接填包名 `dsh-selection-annotations`；访问不了就从本地目录装，指到仓库所在的文件夹。

装完**完全退出 DSH**（托盘里的图标也退掉）再打开。光刷新网页不行，插件代码是启动时加载的。

## 上手三步

1. 在 AI 的回答上拖选一段话。
2. 选区下面会冒出一排按钮，点「批注」。
3. 在弹出的框里写你想说的，比如「这里的数字按 12 个月重算」。

写完可以接着划下一处，也可以直接发送。你的正文不会被改动，批注是跟着消息一起送过去的附加信息。

## 用起来会遇到的事

### 工具条会慢一拍

划完松手，工具条出现在选区下方，上面有否决、采纳、批注、复制。它横向跟着选区走，但会等你停手一秒才滑过去——拖动过程中它不追着你跑，免得挡住你想选的字。

### 点外面就是保存

批注框点外面等于保存，按 Esc 是放弃。新划出来、一个字没写也没加图的批注，点外面会直接丢掉，不会留下空条目。

鼠标在已经批注过的原文上停半秒，会自动打开那条的编辑框；移开就保存关闭。

如果你**拖动过这个框，或者拉过它的边角**，它就不再自己关掉了，点别处也不会消失。这会儿只有 Esc、或者点开另一条批注能把它收起来——位置是你亲手摆的，它不该突然跑了。鼠标扫到别的批注时，它还是会让位给新的那条。

在框里滚轮往下翻，只滚框里的内容，背后的对话不会跟着一起跑。

### 总览

输入框旁边有个「批注 N」的小胶囊，点开是当前所有批注：出处、原文、你写的字、缩略图都在。上下拖可以调顺序，鼠标移上去能编辑或删除，底下还有清空。最下面一行是插件版本号，遇到问题报给我时带上它。

### 已经发出去的批注

每一轮对话上方有一张卡片，列着这一轮你标了什么。会话被回退时会受影响的那几条会标上「已撤回」并变淡——只是标记，数据没有删。

### 它怎么答的

点开那张卡片里的任意一条，备注下面就是 AI 对这条的答复：结论、理由、以及接下来打算怎么办。理由按 Markdown 显示，该有的列表和代码块都能看见。

答复卡也在一轮的「已完成」下方，收起「已完成」时答复卡只折叠正文，标题留在外面；你自己收起过的卡不会因为展开父级又被弹开。

### 图

批注框里可以直接粘图或者拖图进去，一条最多 4 张、单张 8 MB。默认压成 JPEG，最短边不到 100 像素的保持原样。点缩略图能全屏看，点任意处或 Esc 退出。

图跟着草稿存在浏览器里，刷新页面、切会话都还在；草稿太大了会先丢最旧的图，文字留着。

### 设置

「设置 → 插件 → 划词批注」里能改三样：图片是否压缩与压缩质量、给 AI 看的批注说明、采纳与否决自动填进去的那几个字。

## 数据在哪

| 内容 | 位置 |
| --- | --- |
| 还没发出去的草稿 | 浏览器 `localStorage` 的 `dsh-selection-annotations:draft:<会话 id>`，最多留 24 个会话、200 条、约 3.5 MB |
| 发出去的记录 | 浏览器 `localStorage` 的 `dsh-selection-annotations:sent:<会话 id>`，每个会话 120 条、2 MB |
| 批次、条目、答复 | `$DSH_HOME/selection-annotations/annotations.db`（SQLite，WAL；表 `sessions`、`batches`、`entries`、`drafts`） |
| 批注图片 | 会话附件目录，跟消息一起存 |
| 诊断日志 | `$DSH_HOME/selection-annotations/scroll-trace.log`，只留最近 2000 行 |
| 插件设置 | 浏览器的几个 `localStorage` 键 |

插件不往外面发任何请求，数据只在本机和当前会话里流转；宿主那边的写入接口只认本机回环地址。批注会作为你消息的一部分进入上下文，AI 能读到——这本来就是它的用途。

## 发送那一刻发生了什么

1. 你划词写备注，内容先存在浏览器里（草稿）。
2. 点发送时，插件先把这一批写进本机数据库，再读回来核对条数。
3. 核对不上就不发消息，弹一句提示，批注和附件留在输入框里，你重试就行——重试沿用同一个批号，不会重复。
4. 核对通过才真正发送，批注作为一段机器可读的数据跟着消息走。
5. AI 看完按条写答复，答复落到本机库。
6. 界面每 6 秒拉一次新答复，渲染成答复卡。

第 3 步有时候显得烦，但它的代价是一句话的等待，换来的是「消息发出去、批注却丢了」这种事不会发生。

## 装到别的机器、升级

- 升级后同样要完全退出 DSH 再启动。
- 需要 Node ≥ 22.13，用的是内置的 `node:sqlite`。
- 插件通过 `cordis.patch.yml` 插进当前 profile（`insert` 一条 id 为 `selection-annotations`），不改 DSH 本体。
- 宿主参数 `config.maxPayloadBytes` 控制单条批注的负载上限，默认 512 KB，超了会被拒。
- 调试打点可以在控制台执行 `window.__dshSelectionAnnotations.traceScroll(false)` 关掉。
- 答复轮询间隔是 `src/core/config.js` 里的 `REPLY_POLL_MS`，默认 6000 毫秒。

## 要改代码的话

浏览器侧源码在 `src/`，构建成单文件 `client.js`——DSH 只加载这一个文件。

| 路径 | 干什么的 |
| --- | --- |
| `src/entry.js` | DSH loader 入口 |
| `src/plugin.js` | 组合根：注入依赖、注册槽位、生命周期、界面 |
| `src/core/` | 按职责拆的模块：会话、草稿、台账、同步、锚点、卡片、弹层、样式、文案…… |
| `lib/index.js` | 宿主那半边：认领批注附件、把数据块并进用户消息、存答复、定义工具 |
| `lib/annotations-db.js` | SQLite 存取层 |
| `scripts/build.mjs` | esbuild 打包 |
| `scripts/check-build.mjs` | 校验 `client.js` 和源码是否一致 |

```bash
npm install          # 开发依赖只有 esbuild
npm run build        # 生成 client.js
npm run check:build  # 校验构建产物与源码一致
npm test             # 构建校验 + 全部测试
```

`client.js` 是生成物，别手改。React 由 DSH 提供，打包时按 external 处理。

### 宿主接口

都只接受本机回环请求（Host 必须是 `127.0.0.1`、`localhost` 或 `[::1]`）：

| 路由 | 作用 |
| --- | --- |
| `GET /selection-annotations/session/<会话 id>` | 读整份快照，旧形状也认 |
| `PUT` / `POST` 同一路径 | 写整份快照 |
| `POST /selection-annotations/session/<会话 id>/batch` | 新建一批批注，按批号幂等 |
| `PATCH /selection-annotations/entry/<uuid>` | 写某一条的答复 |
| `PATCH /selection-annotations/batch/<batch_uuid>` | 回填这一批的轮次和锚点 |
| `POST /selection-annotations/debug/trace` | 追加诊断日志 |

### 出问题怎么查

诊断日志一行一个 JSON，带 `session` 和 `build` 字段。发送闸会留三类记录：`gate-post`（开始入库）、`gate-done`（入库与核对结果）、`gate-block`（为什么拦）；批次写失败会留 `batch-post` / `batch-done`，界面上标「未同步」。想知道页面跑的是哪一版，看总览面板底部的构建标记。

## 现在还做不到

- 定位靠 DSH 私有的 DOM 结构，DSH 大版本升级后可能要适配。
- iframe 和 canvas 里的文字划不了。
- 历史轮次被虚拟化时，卡片位置以 DSH 实际渲染的为准。
- 批注库按设备各存一份。会话可以跨设备共享，但在别的设备上发的批注，回到本机看不到「已发送」卡片。让库跟着会话走是后面要做的事。
- 英文界面如果和中文对不上，以中文为准。

## 碰到问题

这个插件是靠真实用法一点点磨出来的，欢迎开 issue，请带上：

1. 插件版本（总览面板底部的构建标记）和 DSH 版本。
2. 你做了什么、希望看到什么、实际看到什么。
3. 能复现的话，步骤写得越小越好。
4. 出事时间前后的几十行 `scroll-trace.log`。

贴日志前先把对话里的私人内容去掉。
