# 划词批注（dsh-selection-annotations）

[English](README.md) · **简体中文**

> 在 DSH 的对话里选中一段文字，写一句批注，随下一条消息一起发给模型；模型的答复按条回到对话里。

对一个完全不写代码的人，它解决的问题只有一句话：**你想让 AI 改的地方，指得准一点。** 不用再写「上面第三段那个第二句话」，直接把它划出来。

这篇说明从「只想用」写到「想改」。前面的部分不需要懂技术，后面的部分给要装、要调、要改的人看。

---

## 第一部分 · 只想用，不想看原理

### 装一次，用一直

1. 打开 DSH 的「设置 → 插件」。
2. 装这个插件：装法有两种，能打开 npm 的就填包名 `dsh-selection-annotations`；装不了就从本地目录装（见[第四部分](#第四部分--安装配置与开发)）。
3. **完全退出 DSH**（托盘图标也退出）再打开。只刷新网页不会重新加载插件。

### 一分钟学会

1. 在 AI 的回答上拖选一段文字。
2. 选区下方出现一排小按钮，点「批注」。
3. 在弹出的框里写你要说的话，比如「这里数字算错了，按 12 个月算」。
4. 继续划下一处，或者直接点发送。

消息发出去时，批注跟着一起走；你写的正文一个字都不会被改。

### 你会用到的五件事

- **指哪改哪**：划一句话就能说「这句重写」「这里换成表格」。
- **采纳与否决**：按钮里有「采纳」「否决」，点一下自动写好【意见采纳】/【意见否决】，你只补理由。颜色会跟着变，一眼看出哪句被否了。
- **带截图说**：批注里可以直接粘图，比描述半天快。
- **回看发过什么**：每一轮对话上方会有一张「已发送的批注」卡片，列着这轮你标了什么。
- **看它是怎么回的**：点开那张卡片里的任意一条，备注下面就是模型对这条的答复——采纳了没有、为什么、接下来打算怎么办。

### 卡住了先看这三条

- 发消息时弹「批注没存进库，这条消息没有发出去」：这是保护机制，怕你的批注丢了。批注和附件还在输入框里，再点一次发送就行，不会重复。
- 装完没反应：多半是没完全退出 DSH。彻底退出再开一次。
- 高亮位置错开一行：刷新页面。这是页面滚动后重新定位的边界情况，刷新即可恢复。

## 第二部分 · 用熟之后

### 划线与工具条

- 划完松手，选区下方出现工具条：否决、采纳、批注、复制。
- 工具条会横向跟着你的选区走，但**故意慢一拍**：停手一秒它才滑过去，拖选过程中不会一路追着鼠标跑。
- 正文上右键也能批注或复制；没选中文字时是系统自己的菜单。

### 批注弹层

- 点框外等于保存，按 Esc 取消。
- 新划出来、既没写字也没加图的批注，点框外会直接丢掉，不会留下空条目。
- 鼠标在某条已批注的原文上停半秒会自动打开它的编辑框；移开鼠标自动保存并关闭。
- 一旦你**拖动过它、或拉过它的边角**，它就不再因为鼠标移开而关闭，也不会因为你点了别处而消失——这时只有 Esc 或点开另一条批注会让它收起。理由是：你都亲手摆好位置了，它不该自己跑掉。
- 面板里滚动滚轮只滚面板内容，不会把背后的对话一起带着滚。

### 总览面板

输入框旁的「批注 N」胶囊打开总览：

- 每条显示出处、引用原文、批注文字与缩略图。
- 拖动手柄调整顺序；悬停出现「编辑」「删除」；底部有「清空」。
- 面板底部有一行构建标记（插件版本），用来确认页面加载的是哪一版代码——提问题时请带上它。

### 已发送的批注

- 每轮一张卡片，位置固定在那一轮的「已完成」上方，默认展开。
- 卡片里列出这轮发出的每一条：引用原文、批注、图片。
- 会话被回退（rewind）时，受影响的批注会标上「已撤回」并压暗，数据**不会被删除**。

### 批注答复

- 模型处理完一批批注后提交答复，每一条带判定：采纳 / 部分采纳 / 不采纳 / 需要澄清。
- 答复卡在该轮的「已完成」下方，按条展示来源、判定、理由、下一步。
- 你收起「已完成」时，答复卡只收起正文，标题仍留在外面；你手动收起的卡，不会因为展开父级又被强行打开。
- 在答复卡里也能继续划线批注，位置会记到具体批次与条目上。

### 图片

- 弹层里可以粘贴或拖入图片；每条最多 4 张、单张不超过 8 MB。
- 默认压成 JPEG（质量 80%）；最短边不足 100 像素的图保持原样。
- 点缩略图全屏查看，点任意处或 Esc 关闭。
- 图片随草稿保存在浏览器里，刷新或切会话后还能继续发；草稿过大时先丢最旧的图片，文字保留。

### 设置

「设置 → 插件 → 划词批注」里可以改：

- 图片：是否压缩、压缩质量、触发压缩的最短边。
- 批注指令：给模型看的说明文字，可编辑、可恢复默认。
- 采纳 / 否决：自动填入的字面（默认【意见采纳】/【意见否决】）。

## 第三部分 · 它是怎么工作的

### 一次发送发生了什么

1. 你划词、写备注，批注先存在浏览器里（草稿）。
2. 点发送时，插件先把这一批批注写进本机数据库，**再读回来核对条数**。
3. 核对不上就不发消息：弹出提示，批注留在输入框，等你重试。这一步是为了避免「消息发出去了、批注丢了」。
4. 核对通过才真正发送；批注作为一份机器可读的数据块随消息交给模型。
5. 模型看完，用 `annotation_replies` 工具按条写答复；答复存进本机库。
6. 界面每 6 秒拉一次新答复，渲染成答复卡；点开已发送条目时，备注下方也会显示这条的答复。

### 数据存在哪

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 未发送的草稿 | 浏览器 `localStorage`：`dsh-selection-annotations:draft:<会话 id>` | 最多 24 个会话、200 条、约 3.5 MB |
| 已发送的台账 | 浏览器 `localStorage`：`dsh-selection-annotations:sent:<会话 id>` | 每会话 120 条 / 2 MB |
| 批次、条目与答复 | `$DSH_HOME/selection-annotations/annotations.db` | SQLite（WAL），表 `sessions` / `batches` / `entries` / `drafts` |
| 批注图片 | 会话附件目录 | 随消息作为附件保存 |
| 诊断日志 | `$DSH_HOME/selection-annotations/scroll-trace.log` | 只留最近 2000 行 |
| 插件设置 | 浏览器 `localStorage` 若干键 | 图片、指令、采纳与否决字面等 |

### 隐私与边界

- 插件不发起任何外部网络请求，数据只在本机和当前会话里流转。
- 宿主侧的写入口只接受本机回环地址的请求。
- 批注内容会作为你消息的一部分进入上下文，模型能看到；这本来就是它的用途。

## 第四部分 · 安装、配置与开发

### 安装方式

- **从 npm 装**（发布后）：在 DSH 插件页填包名 `dsh-selection-annotations`。
- **从本地目录装**：插件页选择从本地目录安装，填仓库路径，例如 `E:\heshujiang\Develop\dsh-selection-annotations`。
- 装好或升级后必须**完全退出 DSH**再启动；只刷新页面不重载插件代码。
- 环境要求：Node ≥ 22.13（依赖内置的 `node:sqlite`）。

### 配置

- `cordis.patch.yml`：把插件加入当前 profile（`insert` 一条 id 为 `selection-annotations`）。不改 DSH 本体。
- 宿主参数 `config.maxPayloadBytes`：单条批注负载上限，默认 512 KB，超过的附件会被拒绝。
- 调试日志开关：控制台执行 `window.__dshSelectionAnnotations.traceScroll(false)` 可关闭滚动诊断打点。
- 回复轮询间隔由 `src/core/config.js` 的 `REPLY_POLL_MS` 决定（默认 6000 毫秒）。

### 宿主的 HTTP 路由

全部只接受本机回环请求（Host 必须是 `127.0.0.1`、`localhost` 或 `[::1]`）：

| 路由 | 作用 |
| --- | --- |
| `GET /selection-annotations/session/<会话 id>` | 读整份快照（兼容旧形状，老客户端不会坏） |
| `PUT/POST /selection-annotations/session/<会话 id>` | 写整份快照 |
| `POST /selection-annotations/session/<会话 id>/batch` | 新增一批批注（按批号幂等） |
| `PATCH /selection-annotations/entry/<uuid>` | 写入某条的答复 |
| `PATCH /selection-annotations/batch/<batch_uuid>` | 补该批的轮次与锚点 |
| `POST /selection-annotations/debug/trace` | 追加诊断日志 |

### 源码布局与构建

浏览器侧源码在 `src/`，构建成单文件 `client.js`（DSH 只加载这一个文件）：

| 路径 | 职责 |
| --- | --- |
| `src/entry.js` | DSH loader 入口 |
| `src/plugin.js` | 组合根：注入依赖、注册槽位、生命周期、界面 |
| `src/core/` | 按职责拆开的模块：会话、草稿、台账、远端同步、锚点、卡片、面板、样式、文案等 |
| `lib/index.js` | 宿主半边：认领批注附件、把数据块并进用户消息、答复存储、工具定义 |
| `lib/annotations-db.js` | SQLite 存取层 |
| `scripts/build.mjs` | esbuild 打包 |
| `scripts/check-build.mjs` | 校验 `client.js` 与 `src/` 是否一致 |

```bash
npm install          # 只有 esbuild 一个开发依赖
npm run build        # 生成 client.js
npm run check:build  # 校验构建产物与源码一致
npm test             # 构建校验 + 全部测试
```

`client.js` 是构建产物，不要手改。React 由 DSH 注入，打包时按 external 处理。

### 调试与排障

- 滚动诊断日志：`$DSH_HOME/selection-annotations/scroll-trace.log`，每行一个 JSON，带 `session` 与 `build` 字段。
- 发送闸会写三类记录：`gate-post`（开始入库）、`gate-done`（入库与核对结果）、`gate-block`（拦截原因）。
- 批次写入失败会标「未同步」，并在日志里留 `batch-post` / `batch-done`。
- 想确认页面加载的是哪一版代码：看总览面板底部的构建标记。

### 已知限制

- 定位依赖 DSH 的私有 DOM 锚点，DSH 升级后可能需要适配。
- iframe 与 canvas 里的文字无法划线。
- 历史轮次被虚拟化时，卡片位置以 DSH 实际渲染为准。
- 批注库按设备各存一份：会话可以跨设备共享（如通过远程连接），但在别的设备上发的批注，回到本机看不到「已发送」卡片。把库跟会话走是后续工作。
- 英文文案若与中文界面不一致，以中文为准。

### 遇到问题请开 issue

这个插件靠真实使用反馈来打磨。开 issue 时请带上：

1. 插件版本（总览面板底部的构建标记）与 DSH 版本。
2. 你做了什么、期望看到什么、实际看到了什么。
3. 能复现的话，按步骤写一遍，越小越好。
4. 相关日志：`$DSH_HOME/selection-annotations/scroll-trace.log` 末尾与出事时间相邻的几十行。

请先去掉对话里的私人内容再贴日志。
